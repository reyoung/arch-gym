# 难度策略

| 等级 | 典型形式 | 主要训练 |
|---|---|---|
| L0 | 10–30 行代码 | 条件、参数、局部抽象 |
| L1 | 1–3 个模块的 toy | 接口、职责、数据结构 |
| L2 | 小型真实或模拟项目 | 依赖、状态所有权、模块边界 |
| L3 | 中型系统 | 并发、异常、兼容、扩展 |
| L4 | 真实复杂决策或对应沙盘 | 多方约束、架构取舍 |
| L5 | 多阶段历史或演进模拟 | 长期成本、反事实、抽象发现 |

规模仅是线索。Builder 同时考虑真实竞争目标、领域前置知识、约束交互、状态交互、需预测的变化、跨边界推理和可用脚手架。小段并发代码也可能困难，大型项目中孤立的接口问题也可能简单。不要为了题目来自明星项目、术语多或轮数足就标 L4；只存在显然选择时，不要求玩家编造替代方案来显示取舍能力。

如果玩家简洁地给出充分依据并快速解决，认可其判断，不以字数少推断推理弱。题目没有实际竞争目标或后续挑战只是重复时提前复盘，下一题再改善约束冲突；不临时追加条件、不延长游戏来维持难度标签。

## 领域适配与降级

第一次真正的概念困惑：用一两句话解释；第二次仍不能设计：给最小实例或简化背景；第三次及以后：建议同训练目标的简化问题。`knowledge_questions` 只统计玩家概念困惑事件，是领域适配信号，不自动认定无法设计，也不降低画像。确认接口契约、失败语义、条件边界或题面歧义使用 clarification，不进入该计数；这种澄清可能恰好体现正确性意识。中性追问不是设计提示，实际提供解法方向才记 hint。

例如生命周期/状态所有权：容器编排 → 小型任务执行器 → 两个后台任务的依赖 → 20 行状态处理。降级保留不变量和决策冲突，移除领域背景、多组件交互或过多约束。候选方案和提示降低单题认知负担，但提示影响评价中的独立程度。

切换前说明目的并获得同意。先 `finish --reason switched` 并短评（直接定案），再按 `select --level N` 找缓存题或委托 Builder 生成更低级题。这是本次选题覆盖，不改变 `current_level`。不根据“不了解 Kubernetes”推断架构弱点。

## 升级与长期画像

仅 `finish --reason completed` 结束轮次后保存 `review_status: pending` 的初评；复核解决前，该局不进入长期画像或自动升级。stopped/switched/evidence-gap 直接定案，之后仍可通过 rebuttal 重开复核。profile 的 `completed_sessions` 统计已完成轮次的 completed 对局，包含 pending；这个计数不代表可用能力证据。能力观察和升级只使用已定案且 `evidence_phase: in-game` 的证据，并继续受下述条件限制。旧状态迁移保留已有 `current_level` 作为基线，之后纠正评价时从该基线重算升级，不把审计中的旧评分重复累加。resume 返回复盘，select/start 要求先 resolve-review。反驳重开已定案对局时，同样暂停使用该局评价；修订保留先前评价审计，定案后只用当前评价，不能重复累计同局旧评。纠正旧局必须显式指定其 session ID。

引用揭晓后的 rebuttal 事件的维度须标 `evidence_phase: post-review`，只用于复盘后的学习反馈，不进入自动等级或独立画像证据。对原独立回答的误读可用原 answer 纠正；中性追问不改变该证据的独立性。

脚本根据已定案的行为评价自动调整**下一局**目标：

- 至少最近两局完成且是新题，核心冲突不同；两局之间不能是同题复习。
- 每局至少四项维度有 medium/high 信心的 3–4 分，均独立完成，没有设计提示，且不是 post-review 证据。
- 两局难度均不低于当前级别；每次最多升一级，最高 L5。
- 两次调整间至少新增两局完成记录。

这是透明的保守启发式，评分仍由 Coach 根据回答形成。玩家在 L3 只做一道题表现好时可以结束并提供下一题挑战建议，不据此永久跳到 L5。玩家可明确要求更高难度；用本次 level 覆盖，或经同意用 set-level 设置自述基线。

长期画像不自动降级：当前 MVP 无法可靠区分领域不熟、题目质量和推理困难。降级由 Coach 根据对话提出并经玩家同意，对本次选题生效。后续若要调整长期级别，结合多局跨领域证据并说明依据。未观察维度不计入强弱项；至少两次中高信心观察才进入 strengths/weaknesses。

## 去重与间隔复习

- 精确：Case ID 或归一化的 repository+document 相同，即使改了文件名也排除；包括中途退出及已揭晓的局。
- 语义：脚本使用最近三局 `core_conflict` 的精确匹配作代理；Builder 必须进一步检查冲突含义与别名，不能声称脚本理解所有语义。
- 迁移：不同领域再次练习相同能力可有价值，说明迁移目标；相同近期冲突需同意后使用 `--allow-review`。新题优先于已暴露题，主题重叠用于排序。
- 复习：缓存不足优先检索新题，无法获取时可提议复习。`--allow-review` 仅表示玩家已同意；命令本身不证明授权。复习成绩不触发自动升级。
