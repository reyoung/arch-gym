# 游戏规则

## 模式与题型

只有两种证据模式：`historical-replay` 和 `sandbox`。三种题型 `historical` / `sandbox` / `toy` 中，toy 的 mode 仍是 sandbox。Toy 是问题规模，不是第三种真实历史。开局明确告知模式。

历史重演只能引入在当前时点可核实的事实。问题的措辞和教学取舍由 Builder 构造，不能声称原作者曾被问过同样的问题。历史选择不是唯一答案，事实上的采用不等于方案最优。最终揭示所选历史片段的来源、遗漏、争议和可验证的结果。

沙盘允许合理变化，但变化在开局前由 Builder 固定，避免因玩家答得好而不断移动目标。可以接受玩家指出的合理假设问题；解释修订，不事后添加条件判错。沙盘参考方案是备选设计，不能被描述成生产验证结果。

## 局长与提问

题目预设 3–5 轮，每轮一个主要挑战。通常为初始设计、需求演进、复杂度挑战、抽象反思；无需机械凑足四轮。实现不允许运行时追加轮次，因此也不会超过产品上限六轮。背景解释、澄清和提示不算新轮次。

优先问“在这些约束下如何组织职责，你愿意承担什么代价？”而不是“你知道某模式吗？”。玩家可以画图、描述接口或给代码，不要求完整项目。需要反馈时点明一个已观察到的推理及其遗漏，不给出完整答案。

不要求玩家预测尚未给出的具体历史事件；考察的是对可能变化的推理。若后续变化对先前方案不利，比较修改成本，不回溯扣除合理的当时决策。简单方案如果满足当前目标并有清晰演进路径，应得到认可。

简洁回答不等于推理薄弱。若关键约束、决策及依据已表达充分，不要求扩写。中性追问只补充缺失信息，不算 hint，也不把已有独立判断改为受提示；透露解法方向才记录 hint。确认输入输出、重试语义、接口契约或题面歧义使用 `event clarification`；仅真正的概念困惑使用 `event knowledge-question`，后者才进入知识问题计数。

只在当前目标确有竞争时邀请比较方案；不存在可信替代设计时，认可简单设计并讨论边界或验证，不为完成比较指标虚构劣质选项。若题目明显过易、后续没有实质变化，提前结束，把更有竞争性的目标留给下一题。

## 退出、切换和恢复

结束请求优先于教学流程；立即结束并短评，不再追问。切换需玩家同意，旧局标记 switched，不算能力失败。finish 结束轮次并揭晓参考内容；仅 completed 将初评保存为 `review_status: pending`，此时不影响长期画像或自动等级。stopped/switched/evidence-gap 直接定案，尊重停止和切换请求；之后仍可通过 rebuttal 重开复核。旧题默认不再选用，再做属于复习。

游玩中 resume 恢复固定快照和已记录对话，不把中断记作失败；待复核时 resume 返回复盘而非新轮次。select/start 必须等 resolve-review 解决待复核状态后才能开始新局。若最近发言未保存，承认记录缺失，不捏造上下文。

## 初评、反驳和定案

正常复盘给出依据与初评后，开放询问：“哪些评价你不同意，或有哪些取舍我漏看了？也可直接结束。”review 展示复盘、当前评价、事件及修订历史；玩家提出评价异议时，使用 `rebuttal --text TEXT [--session-id ID]` 保存原话，再核对原始约束、回答与提示。已定案对局收到反驳会重新待复核；新局开始后纠正旧局必须显式指定旧局 ID。

Coach 判断真伪：有效反驳明确承认并修正；部分成立分别说明接受和保留的部分；错误反驳用原始约束与具体事件反驳，不自动同意，也不为维护初评添加新条件。证据不能确定时说明未知。独立反思和不同意见无需额外批准。

通常讨论 1–2 次，不无限辩论。用 `resolve-review --disposition upheld|revised|uncertain|accepted|skipped --reason TEXT [--assessment PATH] [--session-id ID]` 定案；枚举执行时选一个。upheld 是基于证据维持原评，revised 是修订，uncertain 是证据不足的保留结论，accepted 是玩家明确认可，skipped 是玩家选择不继续复核。revised/uncertain 必须提交六维完整替换评价；保留先前评价审计。玩家说停止/下一局时直接收束，只有明确认可才用 accepted，否则用 skipped，不能迫使其接受。

引用原回答修正误判与引用揭晓后新增论证必须分开：后者标 `evidence_phase: post-review`，不参与自动等级或独立画像证据。详细格式见评价标准。依据实际对局反馈提出可复用的教学改进；核实后仅在已授权范围修改技能，不因未经核实的抱怨自动改规则。

## 验收对照

| 场景 | 预期行为 |
|---|---|
| A 资深玩家 | 按声明可 L3 起步；快速完成可提前复盘；两局不同冲突的充分独立证据后下一局升一级 |
| B 领域不熟 | 解释 → 最小例子 → 建议切换；生命周期目标可从编排系统简化成任务执行器 |
| C 初级玩家 | 经同意降为两个函数/10–30 行代码，继续练习同一职责或状态问题 |
| D 重复 | 精确排除全部暴露历史，排除最近三局相同冲突；必要复习需说明目的 |
| E 不同于历史 | 按当时约束、验证和演进成本评价，不按一致性评价 |
| F 挑战假设 | 记录异议，接受有效反例，修正评价，不强迫回到预设选项 |
| G 主动结束 | 不再提设计问题；立即 finish 并短评 |
| H 资料不全 | 明确缺失，不编造；终止历史局或经同意另开沙盘 |
| I 简洁且充分 | 按已表达的依据评价，不因字少降分，也不机械索要备选 |
| J 契约澄清 | 记 clarification，不计概念困惑；中性追问不污染独立证据 |
| K 有效或部分反驳 | 保存原话，逐项核对并修订；保留先前评价审计 |
| L 错误或无法证实的反驳 | 用原始约束解释维持理由；不能确定则 uncertain，不自动附和 |
| M 待复核后继续 | resume 返回复盘；用户要求下一局时 accepted/skipped 收束后才能 select/start |
| N 旧局纠正 | 显式指定旧局 session ID；重新待复核；揭晓后论证不用于独立画像或自动升级 |
| O 题目缺少竞争目标 | 提前复盘，改善下一题，不靠追加条件或凑轮数加难 |

自动测试覆盖确定性的状态和边界，不能证明真实 Coach 对话质量；需在目标 Coding Agent 中做以上对话验收。
