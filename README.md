# Arch Gym

代码沙盘推演游戏，让新人通过实践训练架构设计能力。

通过动手写代码、应对需求变化和复盘设计决策，帮助新人学习软件架构设计。

## 项目目标

让参与者在一个可运行、可修改的代码沙盘中练习：

- 澄清业务目标、约束和质量要求。
- 划分模块与职责，设计接口及数据边界。
- 比较不同方案的成本、收益和风险。
- 用测试、运行结果和可观测数据验证设计。
- 面对需求变化，逐步演进架构并解释取舍。

## 初步玩法

每一局围绕一个小型业务场景展开，参与者扮演架构设计者，主持人逐轮引入新的需求和约束。

1. **领取任务**：阅读业务背景，确认目标、资源和验收标准。
2. **设计方案**：画出模块与依赖关系，记录关键假设和设计决策。
3. **实现最小版本**：用可运行代码验证最重要的设计。
4. **抽取变化事件**：应对流量增长、新业务规则、外部依赖故障或团队协作变化。
5. **调整与验证**：修改代码，检查功能、性能、可靠性和演进成本。
6. **复盘取舍**：比较预期与实际结果，说明哪些设计值得保留、哪些应当简化。

评价以是否满足场景目标、决策依据是否充分、验证是否有效为主，不以使用多少框架、设计模式或微服务作为得分标准。

## 计划中的内容

- 场景任务书：业务背景、初始约束和验收目标。
- 起始代码：可运行、可测试的最小业务系统。
- 变化事件卡：逐轮引入需求、规模和故障挑战。
- 架构决策记录模板：记录备选方案、取舍与验证结果。
- 主持人指南与复盘问题：帮助新人理解设计背后的原因。

## 当前状态

项目初始化阶段。首个业务场景、技术栈和具体评分规则待确定；当前仓库尚未包含可运行游戏。
